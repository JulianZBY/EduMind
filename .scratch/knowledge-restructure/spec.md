# EduMind 知识库重构（污染根修 + Zettelkasten 式演进）

Status: ready-for-agent

## 问题陈述

2026-10-08 教师实测暴露四个问题：

1. **检索污染（最严重）**：问「秦始皇统一六国」，课件封面却是「TCP三次握手」。
   根因实锤：`vector_store.search` 是纯 KNN top-k，**没有相关度阈值**——库里只有 13 个 TCP
   演示知识点时，任何主题的 top-5 都是 TCP，全量混进生成上下文，回复还标「已融合本地知识库」。
   （注：教师曾误报「不同会话的生成物互通」，排查证实数据层各处均按会话隔离，那是污染造成的错觉，
   前端无 bug。）
2. **资料无管理**：教学资料无删除、无上传记录页；`documents.file_path` 残留 Windows 路径
   （`data\uploads\...`，整库自 Windows 迁来；02 清理后存量即空，剩防御性规范化）。
3. **知识库无组织**：知识点的 学科/章节 字段自入库起全空，无分门别类；跨学科场景无口径。
4. **图谱不可用**：mermaid 平铺，无缩放、无折叠、无下钻。

另有体验项：新建会话弹窗强制勾选参考资料（应为零表单直开）；生成物区版本时间线全量平铺。

## 方案与决策（已与教师对齐，2026-10-08 设计对话；to-tickets 审计后定稿 12 票）

- 方向：**ADR-0007**（Zettelkasten 式演进：知识点为原子 + 文献笔记中间层，不推倒重写）。
- 术语：CONTEXT.md 新增 **未命名备课 / 文献笔记 / 联网检索并入库 / 学科清单**。
- 检索：加相关度阈值（先例：`conflict_distance_threshold`，余弦距离）；未命中诚实说
  「知识库未命中相关内容，由 AI 直接生成」，与「知识库为空」区分。
- 数据清理：TCP 演示数据全清、`data/output/` 历史孤儿文件全清（教师均已批准；dry-run 先行）。
- 会话：新建零表单直开；「未命名备课」→首条消息自动命名→手动改名后停用自动；参考资料备课中随时挂。
- 生成物：时间线按生成物分组、默认折叠、只展开当前版本；全版本留痕口径不变（CONTEXT.md §3）。
- 学科：**清单制**（内置+教师可维护），AI 只能选清单内、选不出归「未分类」、可提议新学科由教师批准
  （批准入口住知识库区）；**主学科唯一**，跨学科走「相关关联」。
- 删除联动（教师已确认）：必删=分块+向量+文献笔记+引用该资料的待审冲突；单来源知识点默认删
  （对话框可勾选保留）；多来源摘除该来源保留节点；关系边随节点；被题目考查的知识点删前提示受影响题目。
- 联网：**手动**按钮「联网检索并入库」，结果按文献笔记入库（来源=网页）→提取知识点→冲突审核；
  不自动联网，生成不直接拼网页内容。
- 图谱：React Flow + 树布局（dagre vs elk 由 spike 票定）；父子包含做树骨架，其余三种关系以线型叠加；
  双击类别下钻；风格过 `docs/style/minimalist-flat.md` 自检清单。

## 测试决策

- 一律离线确定性零成本：能力替身只在 `backend/tests/support/fakes.py`（AGENTS.md 铁律）；
  破坏即阻塞。前端 `npm run lint` / `npm run build` / `npm run check:routes`。
- 真实云端 Key 的冒烟（联网检索、真实向量化）由教师配合验证，不阻塞工单交付。
- 数据清理票（02/03）必须先 `--dry-run` 出清单再真删，删前做 SQLite 与目录备份。

## 范围外

- 不做知识点多学科标签（主学科唯一，跨学科用「相关关联」，CONTEXT.md §5）。
- 不做未命中时自动联网（教师明确选手动扳机）。
- 不改四种关系的模型（「双向链接」= 关系边对称可达，ADR-0007）。
- 不做多人/权限（单用户 `user_id="default"`）。
- mermaid 在图谱区被 React Flow 替换属 12 票范围；其余区域对 mermaid 无依赖，不另立票。
