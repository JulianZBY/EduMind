# 09: 新学科提议与教师批准

**What to build:** AI 归类时认为清单内学科都不合适，可以**提议新学科**（附理由）；教师在知识库区的
待批队列里批准或拒绝。批准后学科进清单，相关的「未分类」知识点随之归类。批准入口住知识库区，
不占用冲突审核（那里只裁决矛盾）。

**Blocked by:** 08（提议流建在学科清单之上——没有清单就没有「清单外」可言）

**Status:** ready-for-agent

- [x] 提议态数据模型：待批提议不进清单、不可被归类选用（审核前不入清单，与冲突「待审」同哲学）
- [x] 入库管道：归类失败时产出提议（学科名 + AI 给的理由 + 涉及的知识点）
- [x] 知识库区待批队列：批准（入清单 + 触发相关知识点重归类）/ 拒绝（提议消亡，知识点留在「未分类」）
- [x] 离线测试：提议-批准-入清单-重归类 全链路、拒绝路径、重复提议去重口径
- [x] `uv run pytest -q`、前端三件套全绿
- [ ] 教师配合冒烟：上传资料触发提议 → 批准 → 学科生效（【收尾】教师执行）

【Ownership】
- 可改：数据模型（提议表/状态）、入库管道（提议产出）、knowledge API 与前端（待批队列）、测试
- 禁区：冲突审核区（语义与队列都不动，ADR-0004/0006）；关系类型集合

【约束】文案：「提议」「批准」「拒绝」（CONTEXT.md 口径）；批准是教师 explicitly 的动作，
不存在自动入清单。
