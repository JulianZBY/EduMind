# 08: 学科清单与知识点归类落库

**What to build:** 内置学科清单，教师在知识库区可维护；上传资料提取的知识点**自动**从清单内
选学科落库（主学科唯一），选不出归「未分类」；新知识点入库时按学科与语义补「相关关联」边
（跨学科连接的主要载体，CONTEXT.md §5）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 数据模型：学科清单表；知识点归类只允许清单内取值
- [ ] 内置基础学科清单（语文/数学/英语/物理/化学/生物/历史/地理/政治/信息技术），教师可增删改
- [ ] 入库管道：提取知识点时由对话模型从清单内选学科，填 `knowledge_nodes.subject`；
  选不出归「未分类」；章节同批尽量填（列已存在，不阻塞）
- [ ] 提示词硬约束：AI 不得自造清单外学科名（防幻觉碎片化）；提议新学科是 09 票的范围
- [ ] 关系更新：新知识点入库时按学科/语义补「相关关联」边（复用既有建边路径，不新增关系类型）
- [ ] 知识库区：学科管理界面（清单增删改）
- [ ] 离线测试：清单内归类、「未分类」兜底、清单维护；对话模型用替身
  （02 清空全部旧知识点后无存量回填负担；若本票先于 02 执行，存量 13 个 TCP 节点按「未分类」处理即可）
- [ ] `uv run pytest -q`、前端三件套全绿

【Ownership】
- 可改：数据模型、入库管道、图谱建边、knowledge API 与前端、测试
- 禁区：四种关系的类型集合（不新增）；冲突审核区（不占它的队列与语义）；提议审批（09 票）

【约束】界面文案用「学科」「未分类」（CONTEXT.md 词条），不出现「taxonomy」「标签」类工程词；
本票不包含新学科提议（09 票）。
