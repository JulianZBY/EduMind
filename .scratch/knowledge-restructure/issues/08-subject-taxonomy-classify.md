# 08: 学科清单与知识点归类落库

**What to build:** 内置学科清单，教师在知识库区可维护；上传资料提取的知识点**自动**从清单内
选学科落库（主学科唯一），选不出归「未分类」；新知识点入库时按学科与语义补「相关关联」边
（跨学科连接的主要载体，CONTEXT.md §5）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 数据模型：学科清单表；知识点归类只允许清单内取值
- [x] 内置基础学科清单（语文/数学/英语/物理/化学/生物/历史/地理/政治/信息技术），教师可增删改
- [x] 入库管道：提取知识点时由对话模型从清单内选学科，填 `knowledge_nodes.subject`；
  选不出归「未分类」；章节同批尽量填（列已存在，不阻塞）
- [x] 提示词硬约束：AI 不得自造清单外学科名（防幻觉碎片化）；提议新学科是 09 票的范围
- [x] 关系更新：新知识点入库时按学科/语义补「相关关联」边（复用既有建边路径，不新增关系类型）
- [x] 知识库区：学科管理界面（清单增删改）
- [x] 离线测试：清单内归类、「未分类」兜底、清单维护；对话模型用替身
  （02 清空全部旧知识点后无存量回填负担；若本票先于 02 执行，存量 13 个 TCP 节点按「未分类」处理即可）
- [x] `uv run pytest -q`、前端三件套全绿

【Ownership】
- 可改：数据模型、入库管道、图谱建边、knowledge API 与前端、测试
- 禁区：四种关系的类型集合（不新增）；冲突审核区（不占它的队列与语义）；提议审批（09 票）

【约束】界面文案用「学科」「未分类」（CONTEXT.md 词条），不出现「taxonomy」「标签」类工程词；
本票不包含新学科提议（09 票）。

### 2026-10-08：票 08 实现交付，待协调者安排独立复核

- 范围仅本票；未实现新学科提议、审批模型或队列（票 09），未添加联网入库端点（票 10）。保留并收窄旧执行留下的学科测试替身，未引入生产假响应。
- `subjects` 为归类与维护共用的清单事实源；首次初始化内置十个基础学科和不可更名／删除的「未分类」。重启不复活教师已删除的基础学科。
- 主学科为单一字符串。提示词注入当前清单、禁止自造学科／多值；模型返回清单外、缺失或数组时归「未分类」。章节同批尽量提取。落库时重验当前清单，防止提取后清单变化留下非法名称。
- SQLite 幂等触发器同时覆盖新表与已有知识点表：原有空值／清单外值归「未分类」，原始 SQL 写入受约束；清单更名联动知识点，删除清单项将知识点归「未分类」，均在同一事务内完成，不删除知识点与关系。
- 四个薄端点：`GET／POST /api/v1/knowledge/subjects`、`PATCH／DELETE /api/v1/knowledge/subjects/{subject_id}`。维护业务在知识引擎，带完整 OpenAPI 描述、示例及错误码；前端接口类型通过 `npm run gen:api` 生成。
- 新入库知识点复用建边入口：按同学科与标题语义补「相关关联」，各至多五个候选；语义复用标题向量索引与既有检索距离阈值。不把「未分类」当同学科连接，不新增关系类型；相关关联对称去重，拒绝自环、非法关系与未入图端点。冲突待审仍不入图。
