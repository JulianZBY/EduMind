# ADR-0001：冲突检测收敛为「定义冲突 + 教师审核」

- 状态：已接受（设计期）
- 日期：设计期（原件文件时间 2026-09-15；入库日 2026-09-25）
- 相关：ADR-0004（三类别与差异化审核动作，演进本文对两类的结论）、
  ADR-0006（当前检测范围的自述）、`app/knowledge/conflict.py`

> 以下为原件**照录**：逐字未改，只去掉了原件的一级标题行（它就是上一行）。正文为什么不补写、与后续
> ADR 的关系，见文末「入库说明」。

DESIGN v2 原规划三类冲突（定义冲突、结构冲突、常识存疑），最终只实现定义冲突：同名或近名知识点的内容矛盾交 LLM 比对，入待审队列，教师三选一（接受新 / 保留旧 / 并存），**审核前新节点不入知识图谱**。原因：常识存疑是 LLM 校验 LLM 自产知识，几乎不会触发；结构冲突依赖可靠的图谱关系比对，误报率高；同名 SQL 精确匹配对 LLM 抽取的标题波动（「TCP三次握手」vs「三次握手过程」）过于脆弱，故增加 embedding 相似度预筛（阈值内候选交 LLM 比对，复用既有 sqlite-vec 设施）。

## Considered Options

- 三类全做：成本高，两类实际不触发或不可靠（已弃）
- 仅同名精确匹配：演示材料稍变即漏检，现场评委上传新文件即穿帮（已弃）
- 全砍冲突检测：放弃 DESIGN 宣称的差异化亮点（已弃）
