# ADR-0007：知识库组织采用 Zettelkasten 式演进（知识点为原子，不推倒重写）

- 状态：已接受（2026-10-08 教师实测反馈后的设计对话定案）
- 相关：ADR-0003（能力注册）、ADR-0004（冲突类别）、ADR-0006（检测范围）、
  CONTEXT.md 第 4/5 节（教学资料 / 知识图谱）、`app/knowledge/pipeline.py`、`app/knowledge/graph.py`

## 背景

教师实测暴露知识库的组织缺陷：检索无阈值导致跨主题污染（问「秦始皇」出「TCP 三次握手」，
检索是纯 KNN top-k、永不落空）；教学资料与知识点的关联无管理入口（资料无删除、无来源记录）；
知识点的学科 / 章节字段从入库起就是空，没有分门别类；知识图谱用 mermaid 平铺，无缩放与下钻。
用户提出「参考 Zettelkasten 重新构建知识库的整理方式」，面临推倒重写与在现有模型上演进的取舍。

## 决策

- **演进，不重写**：知识点仍是知识图谱的原子单位（内容、学科、章节、难度、来源的既有模型不变），
  冲突审核、来源引用、四种关系全部继续有效。Zettelkasten 作为**组织方式**叠加，不是替换原子模型。
- **文献笔记成为「教学资料 → 知识点」的中间层**：一份教学资料入库时自动生成一张文献笔记
  （资料摘要 + 由该资料提取的知识点索引）；资料的管理入口（查看 / 删除 / 关联治理）落在文献笔记上。
  删除教学资料时的联动口径（知识点去留）另立票记录。
- **「双向链接」不新增关系类型**：落地为既有关系边的对称可达——「相关关联」本身对称；
  「前置依赖」「推导关系」有方向但界面可逆向导航。Zettelkasten 词汇到本项目翻译为关系图，
  不在四种关系之外造第二套链接体系。
- **学科分类作为结构化索引**（Zettelkasten 的结构笔记角色）：由入库管道自动归类、随库演化更新。
  口径（2026-10-08 定案）：**清单制**——内置基础学科清单，教师可维护；AI 只能从清单内选，
  选不出归「未分类」，认为都不合适时可提议新学科、教师批准后入清单（批准入口住知识库区，
  不占用冲突审核）；**主学科唯一**，跨学科联系用「相关关联」表达，不做多学科标签。
- **知识图谱视图按思维导图形态重做**（缩放、折叠、按类别下钻），替换 mermaid 平铺；
  可视化库选型与「四种关系在树形视图上的呈现」另票记录。

## 被否决的替代方案

1. **推倒重来：卡片模型（文献笔记 / 永久笔记 / 双向链接）替换知识点模型**。
   否决理由：等于重写入库管道与六区中的三个区（知识库 / 知识图谱 / 冲突审核），
   弃用已经扎实的冲突审核与溯源资产，工作量数倍而收益重叠。
2. **维持现状，只修检索阈值**。否决理由：污染只是症状，资料无管理、无分类、图谱不可用
   是同一场病；只修阈值救不了知识库的可维护性。

## 后果

正面：既有资产全部复用；「资料 → 文献笔记 → 知识点」的链条让删除联动与溯源有了清晰锚点。

代价与约束：文献笔记是新的入库产物，解析管道、知识库区界面、删除联动都要为它补代码；
本记录只定方向，分类口径、删除联动、可视化选型各自另票落地。
