# ADR-0006：冲突检测范围（三类别落模型，两类检测暂缓）

- 状态：已接受（票 11）
- 日期：2026-09-24
- 修订：2026-09-25 —— 修正背景里「ADR-0001 没有原始文本」这一前提（原件已找回并照录归档，
  见 ADR-0001 的「入库说明」）；范围、类别与暂缓项均未变
- 相关：ADR-0001（检测口径的原始决策记录，正文已照录归档）、ADR-0002、ADR-0004、
  票 01（文档基线）、票 11（冲突三类别）、`docs/api/conflicts.md`、
  `app/knowledge/conflict.py`、`app/db/engine.py`

## 背景

仓库里有若干处把「定义冲突的检测与教师裁决」标注为 **ADR-0001**（代码注释、配置注释、
既有规格文本），而那条记录的正文长期不在仓库里——票 01 只重建了 0002~0005，
悬空引用会让读者以为有一条可查的决策，实际查不到。

**2026-09-25 这个前提变了**：原件在设计期材料目录里找到，已**照录**归档为
`docs/adr/0001-conflict-detection-convergence.md`（正文不改写，找回与照录的缘由见该记录的「入库说明」）。
本文自述当前**真实**的检测范围，并承接 ADR-0001 的检测口径；冲突的类别模型与差异化审核动作
（定义冲突 / 结构冲突 / 常识存疑，三选一 / 两选一 + 编辑修正后入库）由 ADR-0004 决定。
与 ADR-0001 的两点差异：① 原件把结构冲突与常识存疑判为「不实现」，本文把结论降级为**检测暂缓**
（数据模型与审核动作先落地）；② 类别的动作集合与终态由 ADR-0004 定义，本文不重复。

## 决策

- **检测只做定义冲突**。实现口径（`app/knowledge/conflict.py`）：同名精确匹配 +
  标题向量近名预筛（阈值 `conflict_distance_threshold`，余弦距离）→ 阈值内候选交 LLM
  判断两段描述是否矛盾 → 命中即写入待审队列。
- **审核前新知不入知识图谱**（CONTEXT.md「待审」）。同名且比对无矛盾的重述按同名重复节点
  处理，不入库——图谱里不留重复同名节点。
- **冲突分三类别并落库**：`Conflict.category` = 定义冲突 / 结构冲突 / 常识存疑；
  类别字段落地前的存量冲突**回填为定义冲突**（现有检测只产出这一类），回填是幂等迁移的一部分
  （`app/db/engine.py` 的补列 + 回填，见 ADR-0004「被回填」的约束）。
- **结构冲突与常识存疑的检测逻辑暂缓**：本轮只落数据模型与审核动作，
  检测是重构后的独立功能槽；两类的呈现（图谱现状 vs 三种终态、红旗 + 原文 + 编辑修正）先行落地，
  检测补上时不需要改前端契约。
- **文案不得超前**：面向教师的文案与 README 不得承诺能自动发现结构冲突与常识存疑，
  只能描述裁决动作与形态（CONTEXT.md 第 6 节的文案纪律）。

## 后果

正面：

- 悬空引用有了可查的落点：定义冲突的检测与三选一读 ADR-0001（照录原文），
  当前范围与两类暂缓项读本记录。
- 类别数据模型先落地，检测、呈现、审核动作三侧可以并行；老库与新库的队列呈现一致
  （都从定义冲突开始，不存在「无类别」的中间状态）。
- 口径写死在一个地方：改动检测范围要改的是一条 ADR，而不是各处注释。

代价与约束：

- 教师上传含结构性矛盾或可疑常识的资料时**不会被拦下**——这两类要等检测落地才成立；
  文档与界面必须如实说明，不能靠「形式上支持三类别」冒充功能完整。
- 检测范围是**暂缓**而非否决：落地时需要补提示词、阈值与去重口径，届时另开 ADR 或票记录取舍。

## 被否决的替代方案

1. **凭空重建 ADR-0001 的正文**。否决理由：没有原始文本，重建等于编造决策史。
   （2026-09-25 补：原件已找回，本项从此没有约束目标，但结论继续成立——原件在手时是**照录**，
   仍不新写 0001 的措辞。见 ADR-0001 的「入库说明」。）
2. **删掉所有 ADR-0001 引用、不补新记录**。否决理由：检测口径与「为什么另外两类暂缓」
   就没有可查的落点，悬空引用换成了信息缺口。
3. **本轮把三类检测一次做完**。否决理由：两类检测依赖提示词与阈值反复调优，
   会把类别呈现与审核动作一起拖住（ADR-0004 同一理由）。
