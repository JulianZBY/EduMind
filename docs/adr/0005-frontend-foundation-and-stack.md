# ADR-0005：前端骨架与技术选型

- 状态：已接受（票 01 固化）
- 日期：2026-09-24
- 相关：ADR-0002（后端唯一事实源）、ADR-0003、票 04（前端基座）、`docs/style/minimalist-flat.md`、`docs/architecture.md`

## 背景

重构前的实际状况：

- 整个界面是一个 810 行的单文件 `App.tsx`，功能挤在标签页里：知识管理、备课对话、冲突审核互相挤压。
- 没有路由（切换靠组件内 state），没有 Tailwind、没有 Radix、没有服务端状态库；
  跨组件状态只有一份 `localStorage` 会话存储。
- 依赖只有 `react` + `react-dom`：界面皮肤与交互都是手写内联样式，无法被风格规范约束，也无法被扫描工具检查。
- 备课历史在浏览器里（ADR-0002 已决定改为后端唯一事实源），因此前端必须能消费服务端状态。

同时，接口文档以 OpenAPI 为唯一事实源，前端类型若手抄就必然漂移。

## 决策

- **六区 + 设置的路由骨架**：

  | 区 | 默认路由 | 主区布局 |
  | --- | --- | --- |
  | 备课会话 | ✅ 默认 | 二级侧栏（会话列表）+ 主区对话轴 |
  | 知识库 | | 二级侧栏（资料列表）+ 主区详情 |
  | 生成物 | | 二级侧栏（按会话分组）+ 主区版本中心 |
  | 知识图谱 | | 主区直铺图谱画布 |
  | 冲突审核 | | 主区直铺冲突队列 |
  | 题库 | | 二级侧栏（题目列表）+ 主区详情 |
  | 设置 | | 单页表单（编辑密度） |

  **URL 即路由**：每个区、每个选中对象在 URL 上可寻址，刷新与分享不丢上下文。

- **技术选型**：React 19 + Vite + TypeScript；Tailwind CSS + Radix 无头原语 + 自建约 15 个扁平组件；
  `react-router` 管路由；**TanStack Query 管服务端状态**；**zustand 管跨组件 UI 状态**。
- **不用任何现成组件库**：视觉硬标准（零阴影 / 零渐变 / 零灰底 / `border-2 border-black` / `rounded-none` /
  悬停黑白反色）要求皮肤完全可控，组件库默认样式与主题覆写成本高于自建。
- **API 类型由 OpenAPI schema 生成，禁止手抄**：端点注解缺失 = 前端类型缺失，因此票 01 先补齐全部端点注解。
- **不建组件测试缝**：改为「禁用 class 扫描脚本」挂入 lint/build 作为风格守门工具（非测试缝）。
- **交付判定 = 风格文档自检清单**：前端工单以 `docs/style/minimalist-flat.md` 的自检清单逐项核对为 DoD。
- **密度双轨**：数据区（列表、表格、时间线）用工作台密度；空状态、设置、引导用编辑密度。
- **不留兼容包袱**：旧单文件界面与 `localStorage` 会话整体退场，不做灰度共存。

## 后果

正面：

- 六区各占其位，备课对话回归「以会话为中心」的日常主线；管理类功能不再与对话抢空间。
- 服务端状态只有一条通路（TanStack Query），浏览器里不再有第二份事实源，缓存失效策略集中一处。
- 风格可机器检查：禁用 class 清单让「看起来跑偏了」变成构建期失败。

代价与约束：

- 前后端契约完全依赖 OpenAPI：任何新端点必须先有 `summary` / 描述 / 示例 / 错误码 / tag（见 `backend/AGENTS.md`）。
- 自建组件库是长期成本：约 15 个基线组件需要逐个覆盖默认 / 悬停 / 聚焦 / 禁用状态，并遵守扁平皮肤。
- 风格硬标准会拒绝一些常见但越界的做法（阴影浮起、圆角、灰度分层），改法是加边线与留白，不是放宽标准。
- 前端不写组件测试，回归依赖风格扫描 + 后端契约测试 + 端到端人工核对。

## 被否决的替代方案

1. **引入现成组件库（或组件库 + 主题覆写）**。
   否决理由：零阴影 / 零灰底 / 直角 / 反色悬停需要推翻组件库的大部分默认视觉决策，覆写量大于自建量，
   且组件库的升级会持续带来视觉回归。
2. **沿用单文件标签页结构，只把界面做好看**。
   否决理由：六区互相挤压正是本次要解决的问题；标签页也无法给「按会话分组的版本时间线」这类深层导航留位置。
3. **服务端状态与 UI 状态共用一个全局 store**。
   否决理由：那等于手写缓存、失效、重试与竞态处理，重造一个更差的 Query，并让「什么是服务端事实」变得模糊。
4. **手抄接口类型（或按接口文档人肉对齐）**。
   否决理由：与「OpenAPI 是唯一事实源、前端类型由 schema 生成」直接冲突，漂移只是时间问题。
5. **无路由的视图状态切换（现状做法）**。
   否决理由：URL 不可寻址意味着刷新丢上下文、无法深链到某个会话或某个生成物版本，与「换设备接力备课」冲突。
