# 接口专题文档

这里的每一份文档都只回答**机器表达不了**的协议语义：动作在领域里是什么意思、
多步流程的正确顺序、跨端点的状态约定、错误语义的取舍。

**端点清单、路径、字段、类型、示例以 `/openapi.json` 为准**（Swagger UI 在 `/docs`，ReDoc 在 `/redoc`）。
两者冲突时以 OpenAPI 为准，并当场修这里的文档——不要留两份互相矛盾的说明。

## 什么时候该在这里写一份

- 读 OpenAPI 之后仍然不知道「这个动作在教师那里意味着什么」；
- 一个动作的语义要跨两个端点才能理解（例如「先查再改」的两步动作）；
- 错误码的选择需要解释（为什么是 409 而不是 400）；
- 某个能力的「没配 Key」行为与其它能力不一致，必须说清。

不要在这里写端点镜像文档，也不要复制 OpenAPI 里的字段表。

## 通用约定

### 版本与前缀

- 现行前缀 `/api/v1`。只有破坏性变更才升 `/api/v2`；新增字段、加示例、补注解都不算破坏性变更。
- 无前缀的 `GET /` 与 `GET /health` 是运维入口（服务信息与存活检查），不属于业务接口，不随 v2 演进。

### 错误体形状

错误统一为 FastAPI 的默认形状：

```json
{"detail": "人类可读的说明"}
```

- 校验失败（`422`）的 `detail` 是**列表**，每项含 `loc` / `msg` / `type`。
- 业务错误（`4xx`）的 `detail` 是**字符串**，直接面向教师展示（但仍是中文技术措辞，
  前端如需更适合教师的说法，应自行映射，不要把后端异常原文当界面文案）。
- `5xx` 的 `detail` 是排障信息（例如 `BOCHA_API_KEY 未配置`），不保证对教师友好。

### 错误码选择

| 码 | 何时用 |
| --- | --- |
| `400` | 参数形式合法但内容不可接受（例如文件名含路径分隔符） |
| `404` | 目标资源不存在（冲突、文件、文档、会话） |
| `409` | 目标存在但当前状态不允许这个动作（例如冲突已被裁决过） |
| `422` | 请求体 / 表单 / 路径字段缺失或类型不符（框架自动返回） |
| `500` | 未捕获异常，包含「外部能力没配 Key」这一类配置问题 |
| `502` | 外部模型返回了无法使用的结果（例如试卷题目解析不出来、互动内容不是单文件 HTML） |

### 单用户与身份

所有接口固定作用于 `user_id="default"`。请求里没有身份字段，也不接受身份参数；
不要把「教师 id」写进前端逻辑。
