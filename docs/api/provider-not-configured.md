# 未配置（provider_not_configured）：云端能力没配好时的行为

**产品没有假数据兜底**：任何云端能力（LLM 对话 / 生成、语音转写、网络搜索、云端 PDF 解析）未配置时，
相关接口不返回演示用占位结果，而是返回 `503` 与一段**面向教师的引导文案**，指向设置页：

```json
{"detail": {"code": "provider_not_configured", "message": "…去设置页配置…"}}
```

异常定义在 `backend/app/core/errors.py`（`ProviderNotConfigured`），
全局 503 处理器在 `backend/app/main.py`。

## 各能力未配置时的行为（重要：并不是全都报错）

| 能力 | 未配置时的行为 |
| --- | --- |
| LLM 对话 / 生成（意图分析、课件 / 教案 / 提纲 / 试卷 / 互动内容、冲突比对、图谱提取、视觉解读） | `503` + 引导。`GET /health` 的 `llm_provider` 为空即未配置；所有「要动用模型」的操作返回 `provider_not_configured` |
| 语音转写 | `503` + 引导。需要阿里云百炼的 paraformer Key（专用 `ASR_API_KEY`，与千问 MaaS 的 Key 不通用）——千问 MaaS 不提供转写服务，上传录音时直接得到 503，不会落一条「失败」记录 |
| 网络搜索（博查） | `503` + 引导。需要 `BOCHA_API_KEY`（或在设置页把网络搜索指到博查） |
| 向量化 | **不报错**：回落本地 hash 向量（真实算法，不是假数据），可入库、可检索，但排序不具语义意义，检索质量降级 |
| PDF 解析 | 默认策略 `mineru_then_pypdf`：mineru 失败自动退本地 pypdf；显式 `mineru` 且缺 `MINERU_TOKEN` 时报配置错误 |

一句话：**只有云端能力受「未配置」影响，本地链路（上传、解析、分块入库、会话与生成物版本）照常可用**。

## 配置优先级

```text
设置页（添加供应商 + 粘 Key）  >  .env 引导默认  >  代码默认
```

- `.env` 是**引导默认**：第一次跑起来靠它，之后在设置页改过的值优先。
- 设置写穿后**即时生效、无需重启**；回读只给掩码，任何响应与表单都不回显明文。
- 「什么都不配」时服务照常启动，不会失败——只是涉及云端能力的操作返回 503 引导。

## 配置指向未实现的名字时

配置指向一个**未实现的名字**（例如 `llm_provider=unknown`）时工厂立即抛 `ValueError`，
服务不会静默回落到任何假实现。与「缺 Key」同理：静默回落会让「我明明配了」变成「怎么结果还是假的」，
症状比报错难查得多。

## 测试替身（只在 tests/ 存在，不进产品）

自动化测试不依赖真实 Key：四个能力替身（假 LLM / 假转写 / 假搜索 / 假嵌入）都在
`backend/tests/support/fakes.py`，离线、确定性、零成本，只在 `tests/` 里存在；
产品代码里没有任何假数据兜底实现。

## 前端引导

前端在「要动用云端能力」的入口放 **ProviderMissingNotice** 引导条
（`frontend/src/areas/settings/ProviderMissingNotice.tsx`）：未配置时教师先看到「去哪配」，
而不是等操作失败才撞上 503。面向教师的文案统一说「未配置 / 去设置页配置」，
不用工程词（见 `CONTEXT.md` 措辞纪律）。
